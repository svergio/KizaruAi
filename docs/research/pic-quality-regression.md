# Регрессия качества pic — разбор

Дата: 2026-10-09. **Исторический разбор:** скрипт форензики и его выгрузки удалены при чистке. Эталоны 7 октября и выгрузки зонда тоже удалены (2026-10-09). Выводы ниже уже применены в коде; итоговое качество `render` — в демо-видео из [README](../../README.md#-демо).

## Вердикт

Падение качества — из-за **алгоритма и атласа глифов**, а не из-за Discord. Gray-бенч по MSE, которому «нравился» details, — **плохой критерий** для внешнего вида. Решение: вернуть классическую компоновку для `line`/`render` и короткую shade-рампу, а мягкий словарь details оставить **только** в отдельном режиме `details`.

## Что сравнивали

Хорошие кадры от 2026-10-07 (до unicode-пака и слияния details):

| Файл | Настройки |
|------|-----------|
| `couple2`: line и render | scale=2, cells=160 |
| `gwyndolin`: line и render | scale=2, cells=200 |

Тогда: shade-рампа 13 глифов, measured line 111, без `details_patterns.json`, компоновка — классический NN.

## Причины (по убыванию)

### 1. Компоновка: классический NN → жёсткие пороги по разбросу (главная)

Было (7 октября):

```text
bg = shade(window_mean)
nearest = argmin L2(quad, LINE_PATTERNS)   # shade + measured вместе
return nearest if nearest is measured else bg
```

Стало после unicode/details:

```text
spread = max(quad) - min(quad)
if spread >= 0.45 → ближайший только среди MEASURED
elif details and spread >= 0.08 → ближайший среди DETAILS (41)
else → shade(window_mean)
```

На `couple2` (cells=160, scale=2) доля ячеек с measured-линией упала с ~11.1% до ~0.67%: средние тона ушли в плоский shade, лица превратились в чёрные пятна.

### 2. Shade-рампа 13 → 22 глифа (главная причина «грязи»)

В рампу попали Braille (U+28E4 / U+2809 / U+2840) и плотная геометрия. На `couple2` ~99.4% ячеек line стали shade, чаще всего ◽ (~39%) и ◯ (~25%) → «соты» и мутные полутона.

### 3. Тонкий словарь details на line/render (вторичная)

Мягкий атлас: 255 кандидатов из зонда → 96 после первой упаковки → 41 после чистки декоративных глифов. Пока `details=True` был по умолчанию для line/render, средний разброс (`0.08 ≤ spread < 0.45`) загонялся в этот бедный атлас. Gray-бенч показывал небольшой выигрыш по MSE, а глазами было хуже.

### 4. Словарь line 111 → 153

Добавлена геометрия. Вторично относительно пунктов 1–2.

### 5. Gray-бенч как оракул (не причина, а ложный ориентир)

- На вход энкодеру идёт цветной RGB, двойного «серого» в коде нет.
- Бенч рисует глифы → переводит в серый → bicubic → MSE с исходником. MSE может падать, когда картинка выглядит хуже (соты, раздавленные лица).

### 6. Шрифт / scale

Размеры холста те же, что 7 октября — не регрессия.

## Что сделано / рекомендовано

1. Для `line` / `render` — классическая компоновка без порога `LINE_THR` (в коде: `np.where(nearest >= _SHADE_COUNT, nearest, bg)` в `core/image/ascii.py`).
2. Короткая shade-рампа без Braille (сейчас `core/image/assets/shade_ramp.json`, подбор — [pic-luma-bench.md](pic-luma-bench.md)).
3. `details` — отдельный, четвёртый режим; только в нём работают пороги `LINE_THR` / `DETAILS_THR`.
4. Качество проверять сравнением стоп-кадров со старыми эталонами и глазами в размере Discord, а не только MSE.
