- Same vectors usable for embedding-matrix init (not only a word list).

## How it plugs into word training

Problem: Word LSTM vocab is built with `min_freq` (`core/text/tokenize.py`). Rare Discord slang falls to `<unk>` even when the surface form is a normal Russian word.

Do **not** dump the full 500k Navec list into the training corpus. Merge a **small whitelist** (seeds / slang list) into vocab, optionally copy Navec rows into `nn.Embedding`.

### 1) Build whitelist from contest seeds

```bash
python -m training.prep_embedding_vocab ^
  --seeds experiments/shared/seeds.json ^
  --check-ckpt checkpoints/kizaru_word.pt
```

Writes `seed_whitelist.txt` (tokens present in Navec) and `seed_missing.txt` (e.g. brand names like `зиртек`).

### 2) Next word finetune / retrain

```bash
python -m training.train --level word ^
  --whitelist data/embeddings/navec_hudlit/seed_whitelist.txt ^
  --init-navec --embedding-size 300
```

- `--whitelist` — keep listed tokens even if corpus freq `< min_freq`, and append seed-only tokens.
- `--init-navec` — copy matching rows from `model.safetensors` into `model.encoder` (truncates/pads if dim ≠ 300). Prefer `--embedding-size 300` to keep full Navec vectors.
- Helpers live in `core/text/pretrained_vocab.py` (`load_wordlevel_vocab`, `merge_whitelist`, `init_embedding_from_navec`).

### 3) Word-level transformer / GPT / DeepSeek / BERT-gen LM

Char LMs cannot use Navec rows (no word ids). Use `--level word` + the same whitelist/Navec flags on `training.train_lm`. Tok rows live in `model.tok`; optional `--embedding-size 300` keeps full Navec vectors and projects into `d_model` via `model.emb_proj` when sizes differ (keeps winner-ish `d_model=384` / 8 heads).

```bash
python -m training.train_lm --arch transformer --level word ^
  --whitelist data/embeddings/navec_hudlit/seed_whitelist.txt ^
  --init-navec --embedding-size 300 --d-model 384 --n-heads 8
```

Same pattern for `--arch gpt|deepseek|bert_gen`. Workers read checkpoint `level=word` and sample with word detokenize (`evaluate_lm_words` / word `generate_mlm`).

Finetune from an existing `kizaru_word.pt` still needs a vocab-size-compatible path (growing vocab changes `Embedding` / `fc` shapes) — for slang rescue, a fresh word train with whitelist + Navec init is the clean route; or expand checkpoint tensors manually later.

## Coverage on the current corpus (2026-10-05)

`data/corpus/kizaru_lyrics.txt`, 5.89M word tokens, 208 865 types. Navec vocab is 500 004.

| Slice | Share |
|-------|-------|
| Tokens whose word is in Navec | 92.2% |
| Types in Navec | 63.1% (131 776 / 208 865) |
| Model vocab (`freq >= 5`, 65 164 types) with a Navec vector | 80.6% |
| Tokens that become `<unk>` at `min_freq=5` | 4.2% |
| Same, if rare words Navec already knows are whitelisted | 1.7% |

The frequent words Navec does **not** have are mostly Genius page JSON (`apipath`, `lyricsstate`, `annotatable`) plus slang and names (`skrrt`, `feduk`, `lil`). JSON leaves on the next `prepare_data --source genius-cache`; slang stays and keeps a random init.

Navec initializes meaning. It does not teach rhyme: a vector has no line ending. On cleaned bars (25 artists, 3 032 songs, 163k lines) the rhyme zone of adjacent lines matches **3.9%** of the time, **40×** a shuffled baseline, and **5.9%** of lines rhyme with one of the next three. The signal is real and already in the rap data. Classical verse would raise that rate and change the register; it is not a substitute for the missing rap volume.

## Smoke notes

- Seed coverage in Navec: common slang/literary forms yes; proper nouns / drug brands may stay missing → stay `<unk>` or add to `--extra-words` only if you accept random init.
- Do not treat Navec as lyrics corpus; license of Genius lyrics is separate (see project `LICENSE`).
