## Роли

| Роль | Что | Где |
|------|-----|-----|
| Политика | Генерирует строки от сида | word-чекпоинты `gpt` / `transformer` / `deepseek` |
| LLM-сервер | Учитель + судья | Qwen за OpenAI-совместимым API (llama-swap или аналог) |
| Жёсткая награда | Рифма / луп / длина — считается кодом | локально, без LLM |
| Мягкая награда | Предпочтения / оценки от LLM | chat completions LLM-сервера |

## Схема куплета (что просим у LLM сгенерировать / оценить)

Единица — **куплет** (4–8 строк), опционально хук.

```text
[meta]
lang: ru
form: couplet | hook | freestyle
lines: 4..8
rhyme: aabb | abab | free
mood: ...
seed: <сид пользователя или политики>

[body]
line1
line2
...
```

Жёсткие ограничения (считаются кодом, не Qwen):

1. Число непустых строк в диапазоне.
2. Нет почти одинаковых соседних строк (луп).
3. Рифма концов строк: последний ударный слог / 2–3 последние буквы (для начала — дешёвая эвристика для русского).
4. Бюджет символов на строку (например 20–80).

Мягкие оценки (судья Qwen, 0–10 по каждой оси → взвешенная сумма):

| Ось | Смысл |
|-----|-------|
| rhyme | концы звучат намеренно, а не случайно |
| flow | ударения / слоги ложатся под рэп |
| lexicon | сленг и регистр в духе Kizaru |
| novelty | не копия сида и не общая вода |
| coherence | строки про одну сцену |

Судья отвечает **только JSON**. Невалидный JSON → оценка 0, один повтор.

## Два вызова LLM

**A. Переписывание учителем (данные для SFT, опционально).** Выход политики → Qwen переписывает по схеме → сохраняем как предпочтительный текст для будущего SFT / DPO-пары.

**B. Предпочтения судьи (RLAIF).** Один сид → K сэмплов политики → Qwen выбирает лучший или оценивает каждый → JSONL с предпочтениями:

```json
{"seed":"...","a":"...","b":"...","winner":"a","scores":{"a":{...},"b":{...}},"model":"qwen"}
```

## Цикл (когда SFT будет достаточно хорош)

```
seed
  -> policy.sample(K)
  -> фильтр жёсткой награды
  -> llm.judge / llm.rewrite
  -> preferences.jsonl + переписанные тексты
  -> потом: GRPO / REINFORCE на transformer|gpt  ИЛИ  SFT на переписанных текстах
```

Порядок работ:

1. Написать клиент OpenAI-совместимого API в `core/llm/` и проверить, что судья стабильно отдаёт JSON.
2. Офлайн-дамп: сэмплы политики + жёсткие оценки + предпочтения LLM (`data/rlaif/`).
3. Только потом подключать RL-обновление.
