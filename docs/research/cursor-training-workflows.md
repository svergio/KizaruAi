# Cursor-воркфлоу для обучения моделей

Как вести обучение KizaruAi через агентов Cursor — дополнение к промпт-паттернам из [agent-pool-training.md](agent-pool-training.md).

Два взаимодополняющих режима:

1. **Мультиагентный пул обучения** — фазы с ролями, одна GPU, жёсткие гейты.
2. **Цикл проектирования «пользователь ↔ агент»** — уточнения → план → апрув → поэтапная сборка.

Связанные документы: [jef-rhyme-classifier.md](jef-rhyme-classifier.md), [rlaif-song-loop.md](rlaif-song-loop.md), [night-contest.md](night-contest.md), [../training.md](../training.md).

---

## Режим 1 — мультиагентный пул

Та же идея, что в ночных турнирах: **делить по фазам**, а не один мега-агент со всеми логами и всем пайплайном.

### GPU-мьютекс

- На GPU один процесс обучения за раз.
- Доки, пересборка корпуса, разметка на CPU — параллельно можно.
- Очередь на GPU: освободить (Ops) → LoRA → SFT → RL.
- Во время слотов обучения не поднимать текстовые Discord-воркеры и тяжёлые LLM-процессы.

### Роли (пайплайн JEF / DeepSeek, A0–A5)

| Агент | Фаза | Отвечает за | GPU? | Ждёт |
|-------|------|-------------|------|------|
| **A0 Ops** | 0 | Остановить конфликтующие обучения (например `train_lm --arch gpt`), освободить GPU, smoke `nvidia-smi` | кратко | — |
| **A1 Data** | 1 | JEF jsonl: золото RIFMA/Chicago + мягкие схемы от базовой Qwen на сленге/Ars; train/valid/test | только если разметка грузит модель | A0 |
| **A2 JEF-LoRA** | 2 | LoRA на Qwen (бинарная рифма + сленг); гейт F1/ECE | да | A1 |
| **A3 Корпус+SFT** | 3 | Пересборка корпуса (CPU, можно раньше); SFT `deepseek_v2.pt` | SFT — да | A0; SFT — после того как A2 освободит GPU |
| **A4 RL** | 4 | DeepSeek сэмплит пары; JEF оценивает; RL-обновление | да | гейт A2 PASS + SFT A3 готов |
| **A5 Docs** | параллельно | Только документация | нет | апрув плана |

Координатор запускает фазы и собирает метрики гейтов; работу агентов **не переделывает** и все логи обучения в один контекст не тащит.

### Гейты

1. **A0** — GPU свободна; ранний `gpt_v2` не продвигать.
2. **A1** — есть `data/rlaif/jef/{train,valid,test}.jsonl`; train и test не пересекаются.
3. **A2** — F1 + ECE на тесте проходят → артефакт `checkpoints/jef_rhyme_lora/`.
4. **A3** — SFT завершён → `checkpoints/deepseek_v2.pt`.
5. **A4** — только после 3 и 4; цель `checkpoints/deepseek_rl_v1.pt`.

Гейт не пройден → зависимая фаза останавливается; «доделать пайплайн самому» в том же агенте нельзя.

### Что логирует координатор

- Фаза, агент, старт/конец, код выхода.
- Цифры гейтов (F1, ECE, CE) — файлами или короткими строками в RESULTS, без простыней stdout.
- Какой чекпоинт продвинут (или явно не продвинут).

На длинных обучениях не включать `notify_on_output`; статус — через файлы логов/оценок (то же правило, что в agent-pool).

### Чего не класть в одного мега-агента

- «Убей GPT + собери JEF + LoRA + полный SFT + RL + демо в Discord» одним промптом.
- Весь stdout обучения и все решения по фазам в одном контексте.
- Генеративную чат-LLM как судью рифмы — для этого классификатор JEF.
- Схему рифмы как единственный KPI; схемы — мягкие метки от базовой модели.
- Переписывание скриптов `training/` посреди прогона «чтобы эксперимент заработал», если эта фаза не владеет скриптом.

### Связь с agent-pool

Ночные турниры: команды A/B дерутся на замороженном бенче, координатор копирует победителя.

Этот пайплайн — **последовательные фазы с разными артефактами** (данные → LoRA-судья → SFT политики → RL политики), но с тем же мьютексом и правилом «без мега-агента». Паттерны из [agent-pool-training.md](agent-pool-training.md) (сначала жёсткий ресурс, декомпозиция ролей, Plan → Build с апрувом, поправка дрейфа в мега-агента) применяются без изменений.

## Режим 2 — цикл проектирования «пользователь ↔ агент»

Как выбирать архитектуру обучения **до** запуска A0–A5.

### Что сработало (ветка про судью рифмы)

1. **Проблема** — нужен сигнал рифмы для строк (судья / награда), а не ещё больше чат-болтовни.
2. **Поиск** — нашли подход «классификатор на Qwen» вместо изобретения своего судьи.
3. **Отказ** — чат-LLM как судья: не тот инструмент, дорого, плохая калибровка для бинарной рифмы.
4. **Архитектура** — базовая модель размечает схемы на сленге → LoRA-классификатор бинарной рифмы → SFT MiniDeepSeek → RL, где JEF оценивает пары кандидатов.
5. **Апрув плана** — письменный многофазный план (A0–A4 + параллельный A5); пользователь зафиксировал решения.
6. **Мультиагентная сборка** — последовательные GPU-фазы + параллельные доки; координатор только проверяет гейты.

Итог: дизайн заморожен до того, как жечь GPU; агенты выполняют свои куски, а не перепроектируют на лету.

### Чеклист для следующей задачи обучения

1. **Уточняющие вопросы** — KPI (F1/CE/ECE?), базовый чекпоинт, пути к корпусу, лицензия (NC?), что останавливать/не продвигать, замораживать ли Discord.
2. **Рано отсечь неправильные пути** — генеративный судья вместо классификатора; KPI только по схеме; мега-агент «сделай всю ночь».
3. **Короткий план** — фазы, артефакты, гейты, очередь GPU, параллельные CPU/док-агенты.
4. **Апрув пользователя** — решения фиксируются в плане; LoRA/SFT/RL не стартуют до апрува.
5. **Фазовые агенты** — одна роль на фазу; следующая стартует только при PASS гейта.
6. **Док-агент опционально** — описывает процесс, пока идёт GPU-работа; мьютекс не держит.

### Антипаттерны

- Сразу запускать `train_lm`, пока история с судьёй/наградой ещё «возьмём большую чат-модель».
- Расширять рамки после апрува (новая архитектура, новый KPI) внутри агента обучения без нового плана.
- Координатор сам переделывает A2/A3, потому что «быстрее, чем ждать».

## Быстрый старт (оператор)

1. Пройти чеклист режима 2 с пользователем → план утверждён.
2. Если процесс новый — сразу запустить A5 (доки).
3. A0 → освободить GPU; затем A1 (данные) / пересборка корпуса.
4. A2 LoRA → гейт → A3 SFT → A4 RL.
5. Метрики гейтов записывать рядом с чекпоинтами; Discord-воркеры не поднимать до RESULTS.

Для ночных **дуэлей** (две команды, замороженный тест) — промпты из [agent-pool-training.md](agent-pool-training.md). Для **пайплайна** (судья → SFT → RL) — роли режима 1.
