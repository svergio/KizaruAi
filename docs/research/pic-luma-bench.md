# Pic: luma-бенч (на входе цвет, эталон — серый)

Дата: 2026-10-09. Скрипт: [`notebooks/research/pic_luma_bench.py`](../../notebooks/research/pic_luma_bench.py).  
Артефакты прогона удалены 2026-10-09; цифры ниже — итоги того прогона.

Заменяет старый gray-бенч, который давал ложные выводы — см. [pic-quality-regression.md](pic-quality-regression.md).

Артефакты прошлых прогонов не сохранены — скрипт создаёт их заново.

## Протокол

1. В энкодер идёт **цветной RGB** (не pre-gray).
2. Эталон метрики — Rec.601 gray исходника.
3. Сравниваются режимы **line / render / details** (simple не участвует).
4. Glyph PNG → gray → bicubic до размера оригинала → MSE / MAE / лёгкий SSIM.
5. Перебор словаря: `LEVEL_EPS` ∈ {0.04, 0.055, 0.07} из `pack_report_eps_*.json` (подмена shade-рампы на лету).
6. Перебор `details_thr` ∈ {0.06, 0.08, 0.10, 0.16} при `line_thr=0.45` (только режим details).

Настройки как у эталонов 7 октября: `couple2` cells=160 scale=2; `gwyndolin` cells=200 scale=2; `geo_shapes` (проверка форм) cells=160 scale=2.

## Итог сравнения (eps=0.055)

На фото по MSE: **line ≈ details ≪ render**. Details почти совпадает с line (порог на этих кадрах при thr=0.08 срабатывает редко). Render проигрывает по MSE (OKLab + цветовая структура — ожидаемо).

`geo_shapes` — проверка форм, не главный критерий; там MSE шумит иначе (0.04 иногда ниже по line, но решают фото).

## Глазами против эталона 7 октября

Сравнивали эталон 7 октября (`couple2`, line, scale=2, cells=160) с line из бенча бок о бок (файлы сравнения удалены 2026-10-09).

- Структура лиц / силуэты читаются; «сот» нет.
- Рампа eps=0.055 (block/box) **темнее**, чем эталон 7 октября (старый shade-атлас) — полутона сжаты, женское лицо в более глубокой тени.
- Это не повод отказываться от 0.055: eps 0.04 даёт более мелкую рампу и хуже MSE/SSIM на фото; 0.07 режет ступени и проваливает gwyndolin и SSIM.

## Выбранные значения

| Параметр | Значение | Почему |
|-------|-------|-----|
| `LEVEL_EPS` / `shade_ramp.json` | **0.055** | лучший MSE+SSIM на фото |
| `DETAILS_THR` | **0.08** | граница плоского и мягкого среднего диапазона; перебор порога — в пределах шума |
| `LINE_THR` | **0.45** | только верхняя полоса режима details; line/render — классический NN без порога |
