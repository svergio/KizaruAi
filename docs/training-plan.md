# План переобучения: русский рэп (SFT → JEF → RL)

Цель — трансформер, который пишет русский рэп (Kizaru — только имя проекта). Шаги идут строго по порядку. Следующий шаг начинается, только когда приняты критерии предыдущего. Пропуск шага = повтор прошлой неудачи (разбор прошлого RL — в конце).

## Шаг 1. Пулы и микс (`training/build_mix.py`)

1. Перед сборкой прогнать проверки корпуса: `python -m training.check_dataset dupes textdupes script` (описание — [training.md](training.md#проверка-корпуса)). Битые кэши (не тот артист Genius: Arash, Canis, SOH, Kazhe — уже удалены) убираются из `data/corpus/` до сборки, а не фильтром в миксе.
2. Собрать микс: `python -m training.build_mix --mix ru_rap_v1 --dry-run`, посмотреть таблицу пулов, затем без `--dry-run`.

## Шаг 2. SFT заново на чистом миксе

Двухэтапный GPT v2 (BPE 32k, tie weights; чекпоинты только `gpt_ru_v2_*`, prod не трогать без команды):

1. **Претрейн** на `ru_v2_pretrain` (весь `ru_rap` + поэзия/other/pop/rock, `en_rap` ≤15%). Выбор/patience по `val_all` → `checkpoints/gpt_ru_v2_pre_best.pt`.
2. **Дообучение** на `ru_v2_finetune` (85/10/5), `--init-from` претрейна, lr в 3–5× меньше. Выбор чекпоинта и patience по **`val_focus` = val ru_rap** → `checkpoints/gpt_ru_v2_ft_best.pt`.
3. **Сравнение с prod** (`gpt_ru_rap_v1-prod.pt`): bits-per-char на одном и том же `val_ru_rap` + 20 сэмплов с фиксированным сидом от обеих моделей рядом. Prod менять только по отдельной команде.

Сплит по хешу общий: held-out одного микса не попадает в train другого. Токенизатор BPE учится только на train претрейна и лежит рядом с чекпоинтом (`.tokenizer.json`).

Критерии приёмки:

- val_focus (ru_rap) не улучшается `patience` оценок подряд → стоп; лучший `_best.pt` не затирается финалом;
- bpc на val ru_rap не хуже prod (или осознанный регресс с примерами);
- в 20 сэмплах по 8 строк нет строк, повторённых подряд, и нет «а- а- а-».

## Шаг 3. JEF-судья заново

Прошлый судья — бинарный «есть рифма» на смеси классики и шума. Его можно обмануть повтором слова и английскими вставками. Новый датасет:

| Класс | Что | Сколько |
|-------|-----|---------|
| Позитивы | настоящие куплеты русского рэпа (4–8 строк) из `ru_rap` train | 2–3 тыс. |
| Жёсткие негативы | строки той же песни со сдвигом, чтобы соседние не рифмовались; «почти рифмы» (последнее слово заменено похожим по звучанию, но не рифмующимся); реальные нерифмованные куплеты | 1–2 тыс. |
| Ловушки | повтор слова/строки, «yeah yeah», английские строки, теги `[Куплет]`, обрезанные строки | в составе негативов, ≥300 |

Сплит — по песне: строки одной песни не попадают в train и test одновременно.

Гейт приёмки — `training/jef_challenge.py`: контрольный набор из 11 категорий (`pos_couplet`, `pos_quatrain`, `neg_shift`, `neg_near_rhyme`, `neg_unrhymed`, `trap_repeat_word`, `trap_yeah`, `trap_english`, `trap_tags`, `trap_fragment`, `trap_prompt_copy`), не пересекается с данными JEF.

```bash
python -m training.jef_challenge build --out data/rlaif/jef_challenge/ --seed 1
python -m training.jef_challenge eval --judge checkpoints/jef_rhyme_lora
```

Критерии: у позитивов оценка > 0,8, у жёстких негативов и ловушек < 0,2 — минимум у 80% примеров в **каждой** категории (`--min-frac 0.8`). Текущий судья `checkpoints/jef_rhyme_lora` проваливает все 11 категорий. Пока гейт не `PASS` — **RL не запускать**, чинить датасет судьи.

## Шаг 4. RL с исправлениями (`training/train_rl_deepseek.py`)

Что поменять в коде:

1. KL с градиентом: убрать `.detach()` у `lp_pi` в KL (сейчас `kl = (lp_pi.detach() - lp_ref) / n`, градиента нет) или k3-оценка по токенам.
2. Логвероятность — среднее по токенам, а не сумма.
3. Группа 8 вариантов на затравку, 4–8 затравок на шаг.
4. Преимущество — центрирование по среднему группы без деления на std (с группой 2 и std любое отличие давало ±1).
5. Пересчёт логвероятности политики и ref в `eval()` (сейчас политика в `train()` с dropout 0.1).
6. Судья видит только продолжение, без затравки.
7. Отдельный `*_best.pt`, выбор по скользящему среднему награды; периодические — `*_stepN.pt` (сейчас всё в один файл).
8. Штрафы в награде: повтор строк/слов и доля латиницы.
9. Затравки — из `ru_rap` (train микса), а не из общего корпуса со стихами и английским.
10. Логвероятность продолжения — одним прямым проходом, не по токену.
11. 1000–2000 шагов, целевой KL 0,05–0,2.

Критерии приёмки:

- скользящее среднее награды растёт и держится выше старта на ≥0,1;
- KL в коридоре 0,05–0,2;
- val CE микса вырос не больше чем на 5% от SFT;
- в 50 сэмплах: латиница ≤10% строк, повторов строк подряд нет; рифма выше, чем у SFT, на глаз и по `check_dataset rhyme` на сэмплах.

## Где брать ещё данные

`ru_rap` по Genius почти выбран по топ-артистам: из списка `ru_expand.txt` не хватает 357 slug, но это в основном связки `X-and-Y` и опечатки. Что качать:

- **Русский рэп, мид- и андерграунд**: новые slug в `training/artist_pools/ru_rap_extra.txt` (~220, Genius search) и `ru_expand.txt`, затем `python -m training.genius_orchestrator --pools var/dl_pools --download-only` (копии списков в `var/dl_pools`). Сотня артистов по ~100 песен ≈ +4–5 млн токенов. Не-рэп, попавший в рэп-список, — в `artist_pools/ru_rap_exclude.txt` с нужным пулом.
- **Русские песни для `ru_other`** (поп/рок/шансон как вспомогательный пул, ≤20–30% микса): докачать из очищенного `ru_pop_rock_chanson.txt` (~130 проверенных slug: Kino, DDT, Agatha-Christie, 2-bi-2, Zemfira, Sergei-Shnurov, Mikhail-Krug и др.).
- **`stihi_ru`** уже берётся целиком (715 млн токенов) — поэзии хватает с запасом, её долю держать ≤10–15%.

Loss от −83 до +59, KL ≈ 0 (и без градиента). «Лучший» чекпоинт (шаг 154, R_mean 0,984 на одном шаге) перезаписан шагами 200 и 250.
